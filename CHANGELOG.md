## [Unreleased]

### Fixed

- Removed the seven speculative `modules/*.css` 404s from the development and accessibility-QA rendering (tracked as PLAN `O-06`). The requests were attributed to a browser preload scanner and to both `npm run dev` and `npm run qa:a11y`; measured against the gate's own static server, neither holds. They come from `axe-core`: `axe.run()` preloads the CSSOM, and for every `@import` it reads `CSSImportRule.href` — which returns the specifier exactly as authored, `./modules/tokens.css`, not the URL the browser resolved it to — and re-fetches it with `XMLHttpRequest`. An XHR resolves against the page, not against the stylesheet, so `/index.html` requested `/modules/*.css`, `/oferta/lazienki.html` requested `/oferta/modules/*.css` and `/doc/polityka-prywatnosci.html` requested `/doc/modules/*.css`, seven 404s each, while the browser's own seven `css/modules/*.css` requests returned 200 and applied. `npm run dev` issued no such request on any route, before or after the change. The fix removes the ambiguity rather than the log line: `css/style.css` now addresses its modules root-relatively (`@import "/css/modules/tokens.css"`), so the authored specifier and the resolved URL are the same string and no consumer can re-resolve it against a different base. Because those URLs are site-root relative rather than file-system paths, `postcss.config.js` hands `postcss-import` a `resolve` that maps a leading `/` onto the project root and returns every other specifier untouched, so the plugin's own resolver — including `node_modules` lookup — still handles everything else. `css/style.css` stays the canonical entry point, the seven modules keep their source ownership under `css/modules/`, none was merged, moved or inlined by hand, and no dependency was added. Nothing masks a missing file: no redirect, rewrite or fallback was introduced, and `/css/modules/does-not-exist.css`, `/definitely/missing.png` and the two former speculative paths `/modules/tokens.css` and `/oferta/modules/tokens.css` all still return 404. Across the five `qa:a11y` routes the `modules/*.css` 404 count went from seven per page to zero; axe now fetches the same seven files at `/css/modules/*` and gets 200, so the request count is unchanged and only the resolution is corrected. `npm run qa:a11y` still reports `PASS qa:a11y (5 pages scanned, 0 serious/critical violations)`. Under `npm run dev`, `/index.html` and `/oferta/lazienki.html` load all seven modules from `/css/modules/*` with `CSSImportRule.href` and the resolved sheet URL now identical, and the token, base, layout, component, section, utility and subpage rules all apply. Production is untouched: `build:css` still inlines every `@import`, `scripts/verify-css-build.js` still passes, and the regenerated `dist/css/style.min.css` is byte-identical to the pre-change build (SHA-256 `75c3fd0d…92501`, 75,051 bytes), so no deployed page gains or loses a request.

No replacement business data was invented; the `WebSite`, `CollectionPage` and `FAQPage` graphs that describe the web project are untouched and every JSON-LD block still parses. - Resolved the conflict between the lightbox's passive double-tap listener and its `preventDefault()` call (tracked as AUDIT `P2-10` / PLAN `PH8-02`). The double-tap-to-fullscreen `touchend` listener on `.lb-viewport` was registered with `{ passive: true, signal }` while its handler called `event.preventDefault()` on the second tap, so the call was inert and Chromium logged `Unable to preventDefault inside passive event listener invocation.` on every double tap. The suppression it was meant to perform turned out to be load-bearing rather than cosmetic: with it inert, one double tap also produced the browser's synthesised compatibility `dblclick`, which reached the lightbox's own `dblclick` handler and invoked `toggleFs()` a second time, leaving two handlers racing the asynchronous fullscreen state transition for a single gesture. The listener is now registered with `{ passive: false, signal }`, so the call it already made is valid. The handler body, the 350 ms double-tap window, the `toggleFs()` logic, the companion `dblclick` listener and the `AbortController` signal that owns the registration are unchanged, and the `touchstart`, `touchmove` and swipe `touchend` listeners remain passive — `touchend` cannot block scrolling, so the change carries no scroll-performance cost. One double tap now issues one `requestFullscreen()` call instead of two, emits no `dblclick` and no console warning, and still enters fullscreen; single-tap, swipe, arrow-key, Escape, focus-restore and mouse double-click behaviour are unchanged.
- Stopped ScrollSpy from accumulating pending `scrollend` listeners during a scroll gesture (tracked as AUDIT `P2-11` / PLAN `PH8-03`). `onScroll` throttles `compute()` through `requestAnimationFrame`, but called `scheduleComputeAfterScroll()` on every scroll event, and in browsers that support `scrollend` each of those calls registered another one-shot listener. They removed themselves once the event fired, so nothing leaked, but a single sustained gesture left one pending listener per scroll event and they all ran `compute()` in the same dispatch when scrolling stopped. `scheduleComputeAfterScroll()` now guards that branch with a `scrollEndPending` flag: the first call of a gesture registers the listener, later calls return immediately, and the listener clears the flag and removes itself before computing. The flag is also cleared from the module's existing abort signal, so an aborted instance leaves no raised flag behind and a reinitialisation starts clean. The `requestAnimationFrame` throttle and the 120 ms `setTimeout` fallback for browsers without `scrollend` are unchanged, and ScrollSpy's thresholds, offsets and active-section logic were not touched. Measured in headless Chromium through the browser's own listener registry, a continuous smooth-scroll gesture of 33 scroll events previously peaked at 33 pending listeners and one of 51 events at 51, with 396 and 306 section `getBoundingClientRect()` reads inside the single `scrollend` dispatch; the same gestures now peak at one pending listener and perform 12 and 6 reads — one `compute()` pass. Active-section highlighting, the nav-link click path, reinitialisation through `window.SC.nav.initScrollSpy()`, the mobile drawer and the offer submenu behave as before, and with `onscrollend` removed from the window the module still falls back to its timer and computes once after scrolling stops.

The close, previous and next buttons were appended to `<body>` as siblings of the `role="dialog"` element, so the dialog that declares `aria-modal="true"` did not contain the controls that operate it, and assistive technology honouring that declaration could leave Escape as the only discoverable way out. The relocation needed exactly one style change: `.lb-wrap` sets `pointer-events: none`, so `.lb-btn` now declares `pointer-events: auto` the way `.lb-viewport` already did. The controls keep `position: fixed`, and their measured rectangles are identical to the previous body-level DOM at desktop and phone widths. Separately, every homepage offer thumbnail was overridden with `aria-label="Powiększ zdjęcie"`, announcing six images under one identical name; the module no longer sets that label when the image has usable `alt` text, so each control is named by the description already in the markup, and the generic label survives only as a fallback for an image without `alt`. The `oferta/` gallery anchors were already named from their own image `alt` and are unchanged, as are the focus trap, focus restore, Escape handling, arrow and swipe navigation, double-tap fullscreen and the lightbox's visual presentation.

### Changed

- Replaced the hand-duplicated site header and footer with a build-time shared partial architecture. The complete header and footer markup was maintained separately inside all 13 documents, so any change to navigation, footer content, contact details, social links or accessibility attributes had to be repeated up to 13 times; the copies had already drifted into four header and five footer formatting variants. The markup now lives once in `partials/header.html` and `partials/footer.html`, and each page embeds it with two `<!-- @include partials/... -->` directives plus a single `<!-- @layout ... -->` line declaring its page context. A new renderer, `scripts/utils/partials.js`, expands the directives and is shared by `scripts/build-dist.js`, `scripts/check-links.mjs`, `scripts/check-html-assets.mjs` and `scripts/qa-a11y.mjs`, so production output and every existing validation see the same fully rendered document. Nothing is resolved in the browser: there is no `fetch()`, XHR, iframe or client-side include, no new dependency and no framework — `dist/` receives ordinary complete static HTML that renders its header and footer with JavaScript disabled. The three differences that genuinely varied per page are carried by the layout variables rather than by duplicated markup: `base` for site-root-relative references, `home` for homepage anchors, and `active-home` for the homepage's `aria-current="page"`. This preserves each page group's existing destinations exactly — `index.html` keeps its bare `#anchors` (required by the `.dropdown-trigger[href="#oferta"]` and `.nav-menu a[href^="#"]` selectors in `js/modules/nav.js`), `thank-you.html` keeps `index.html#…`, `oferta/` and `doc/` keep `../index.html#…`, and `404.html` and `offline.html` keep their URL-depth-independent `/` forms. The rendered header and footer are byte-for-byte equivalent to the previous markup on all 13 pages, and header and footer screenshots are pixel-identical to the pre-migration build at desktop, tablet and mobile widths. The shared SVG icon registry is untouched: the partials still carry `[data-icon]` placeholders resolved by `js/modules/icons.js`, and the footer social row keeps its Facebook, Instagram, X, GitHub order, its `aria-label` accessible names, `target="_blank" rel="noopener noreferrer"`, and the `.ft-social__label` no-JavaScript labels. Semantic landmarks, the `#footer` and `#footer-heading` relationships, the skip-link target, theme-toggle markup, `#navMenu` / `#dd-oferta` ARIA wiring, the map-consent `<noscript>` fallback and every design-system class are unchanged, and no component CSS was duplicated. The renderer fails the build with a named error when a partial is missing, a variable is undeclared, an `@layout` is malformed or duplicated, an include escapes `partials/`, or any directive or `{{token}}` survives rendering, so a page can never ship without its header or footer. `partials/` is excluded from `dist/`, from `sitemap.xml`, from the HTML checkers and from Prettier, which cannot parse the template syntax. Service Worker cache ownership and strategies, the Netlify build command and publish directory, sitemap contents and the CSS/JS production asset handling are unchanged.
- Replaced the scattered footer and contact icon implementation with one shared SVG icon registry in `js/modules/icons.js`. SVG geometry now exists once, keyed by stable identifiers (`github`, `facebook`, `linkedin`, `instagram`, `x`, `phone`, `email`) taken from Font Awesome Free 7.3.1 and attributed in the module header. Maintained HTML across all 13 documents declares icons as `[data-icon]` placeholders, and `initIcons(root = document)` — wired into the existing `js/script.js` bootstrap behind a `has("[data-icon]")` guard — resolves them with `document.createElementNS`, applying the registry `viewBox`, `fill="currentColor"`, `aria-hidden="true"` and `focusable="false"`; unknown identifiers are left untouched. This retires the three bitmap-backed `assets/img/icons/*.svg` social marks (roughly 94 KB of embedded raster data) that could only be tinted through CSS `filter`, and the four hand-inlined 24 px stroke contact icons duplicated in every page footer. Colour is now inherited through `currentColor`, so `.ft-social__icon`, `.ft-contact-icon` and `.contact-icon` only own size, opacity and transitions, and the `.ft-social img` image-filter rules are gone; footer layout, 36 px social hit areas, hover/focus treatment and both themes are unchanged. Social links keep their `aria-label` as the accessible name and gained a `.ft-social__label` text label that becomes visible under the project's existing `.no-js` strategy, so the controls never render as empty boxes without JavaScript. `assets/img/icons/facebook.svg`, `instagram.svg`, `x.svg`, `tel-40.svg` and `email-40.svg` were removed after a repository-wide reference check. The footer social row now carries four registry-driven links in order — Facebook, Instagram, X and GitHub (`https://github.com/KPKrol85`) — each an icon-only external link owning its own `aria-label`, `target="_blank"` and `rel="noopener noreferrer"`, and each keeping the 36 px hit area the row already used. `linkedin` is registered but currently unused, as SolidCraft has no such destination.

### Build and Tooling

- Made `npm run dev` render the shared partials. The dev command was `live-server --port=15500 --open=index.html --quiet`, which serves page sources straight from disk and would now show pages without their header and footer. It is now `node scripts/dev-server.js`, a small launcher that starts the same `live-server` on the same port with the same entry file through its Node API and adds one middleware: HTML requests are answered with the page rendered through `scripts/utils/partials.js`, everything else is served by `live-server` unchanged. The middleware re-injects `live-server`'s own reload snippet, so live reload still works, and because `partials/` sits inside the watched root, editing a partial refreshes the browser and updates all 13 pages at once. A render error returns HTTP 500 with the failing page and reason instead of a silently broken document. `partials/` was added to `.prettierignore`, as Prettier's HTML parser rejects the `{{#if}}` template syntax; no other formatting behaviour changed.
- Stopped local agent and worktree directories from being discovered as production content. `scripts/build-dist.js` and `scripts/generate-sitemap.mjs` each walk the project tree for HTML files, and their exclusion sets covered `.git`, `node_modules` and `dist` — plus `build` in the sitemap — but not `.claude` or `.codex`, which `.gitignore` already records as local agent worktrees. With `.claude/worktrees/**` present, every sibling worktree's pages were copied into `dist/` and emitted as `<loc>` entries, including each worktree's own nested `dist/` output, because both scripts test only the first path segment against their exclusion set. `.claude` and `.codex` are now members of `EXCLUDED_TOP_LEVEL_DIRS` in `scripts/build-dist.js` and `EXCLUDED_DIRS` in `scripts/generate-sitemap.mjs`, so traversal skips them at the top level and never descends into any current or future worktree beneath them. A local `npm run build:dist` with `.claude/worktrees/` and `.codex/` populated previously staged 19 HTML files and wrote 15 sitemap URLs; it now stages the 13 real HTML documents with no `.claude` or `.codex` path anywhere under `dist/`, and `dist/sitemap.xml` again lists exactly the 10 public URLs, with `404.html`, `offline.html` and `thank-you.html` still excluded by filename. Netlify clean-checkout deploys were never affected, as neither directory exists there; the change makes local production builds deterministic.

- Moved CSS and JavaScript minification into the production build so generated artefacts have a single owner. `build:css` and `build:js` now write `dist/css/style.min.css`, `dist/js/theme-init.min.js` and `dist/js/script.min.js` instead of placing them beside their sources, `watch:css` and `watch:js` follow the same outputs, and `css/style.min.css`, `js/script.min.js` and `js/theme-init.min.js` were removed from the maintained tree, with `/css/*.min.css` and `/js/*.min.js` added to `.gitignore` so they cannot reappear. `build:dist` is now `node scripts/build-dist.js && npm run build && npm run build:sitemap`: `scripts/build-dist.js` clears and stages `dist/` first — it no longer requires or copies source-tree minified files — and the asset build fills it afterwards, so the `dist/` cleanup can no longer delete freshly generated assets. `scripts/verify-css-build.js` and `scripts/verify-js-build.js` validate the artefacts in their new `dist/` locations, and the JS check now covers the theme bootstrap bundle as well, replacing the `ensureRequiredFilesExist()` guard dropped from `scripts/build-dist.js`. Development is unaffected and keeps loading `css/style.css` and the `js/script.js` ES modules; the published asset URLs (`/css/style.min.css`, `/js/script.min.js`, `/js/theme-init.min.js`), the `sw.js` precache contract and the Netlify publish directory are unchanged.
- Added a production asset pipeline that builds `css/style.min.css` with PostCSS and bundles `js/script.min.js` and `js/theme-init.min.js` with esbuild, each followed by a build verification script (`scripts/verify-css-build.js`, `scripts/verify-js-build.js`).
- Added the `dist/` deployment build (`scripts/build-dist.js`) that copies runtime files, rewrites references to minified assets, and generates the sitemap for the configured site URL.
- Added Netlify deployment configuration: `netlify.toml` with the `npm run build:dist` command and `dist` publish directory, `_redirects` for canonical paths and the 404 fallback, and `_headers` with security headers including a Content-Security-Policy.
- Added a `sharp`-based image pipeline (`scripts/images.js`) that generates responsive AVIF, WebP, and JPG variants from `assets/img-src/`.
- Added a local development workflow based on `live-server` with separate CSS and JS watch tasks, and Prettier formatting scripts.
- Made the deploy command regenerate the assets it publishes. `build:dist` gained `npm run build`, so the Netlify build command runs the PostCSS and esbuild steps with their verification scripts as part of the deploy; previously it copied whichever `css/style.min.css`, `js/script.min.js` and `js/theme-init.min.js` happened to be committed, and a commit touching `css/modules/**` or `js/modules/**` without a local `npm run build` deployed stale assets silently. `qa:lhci` dropped its leading `npm run build`, which `build:dist` now performs, leaving its expanded chain identical. The step order within `build:dist`, and the `ensureRequiredFilesExist()` guard this change originally kept in `scripts/build-dist.js`, were both superseded later in this cycle by the move of the minified artefacts into `dist/` — see "Moved CSS and JavaScript minification into the production build" above for the contract that ships.
- Completed the repository hygiene controls. The `.gitignore` no longer carries a duplicated "Test and report output" section — a single block now lists `/test-results/`, `/playwright-report/` and `/.lighthouseci/`. A new `.gitattributes` declares one line-ending convention for tracked text files (`* text=auto eol=lf`) and marks the binary asset extensions present in the project (`.avif`, `.ico`, `.jpg`, `.png`, `.webp`, `.woff2`) as `binary` so normalisation can never rewrite them; previously no such file existed, line endings depended on whichever tool last wrote a file, and real changes were buried in whole-file line-ending diffs. The two duplicate gallery renditions `assets/img/gallery/elec-01-2048x1536 (1).avif` and `assets/img/gallery/tilling-04-768x576 (1).avif` were removed — no page, stylesheet, script or manifest referenced them and both had non-suffixed counterparts — so they no longer ship to `dist/`. The `.gitattributes` rules apply to files already tracked only after the working tree is renormalised, which is a separate Git operation.
